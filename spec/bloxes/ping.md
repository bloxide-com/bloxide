# Blox Spec: `Ping`

## Purpose

The Ping actor initiates and drives a ping-pong exchange with the Pong actor. It demonstrates:

- **Nested composite state**: `Operating(Active, Paused)` — three-level deep hierarchy.
- **Internally-driven pause**: After `PAUSE_AT_ROUND`, `Active` itself transitions to `Paused` (no external signal). `Paused::on_entry` calls `schedule_resume` (from `blox-ctx-ping-pong`) to schedule a `PingPongMsg::Resume` delivery after `2000 + round * 500` ms.
- **Timer-driven events**: The `Resume` event is generated by a one-shot timer owned by the Ping blox itself — not by any external actor or bootstrap task.
- **Event bubbling**: `Paused` bubbles unrecognised events (e.g. stray `Pong`) to `Operating` via implicit bubble.
- **One ping per round**: `Active::on_entry` runs only `send_initial_ping`, which fires once when the machine is fresh (`round == 0` → sends `Ping { round: 1 }`). Each subsequent `Pong`/`Resume` runs the transition actions `increment_round` then `forward_ping`, sending exactly one `Ping` for the new round. A `Pong` that matches no guard is a `stay` — no self-transition, no re-entry.
- **Self-terminate via Decision::Done**: When all rounds are complete, `Active`'s guard returns `Decision::Done` — the actor runs the Stop cleanup ritual (exit chain + `on_init_entry`), the runtime reports `ChildLifecycleEvent::Done` to the supervisor, and the run loop ends the task. No `Done` state or `is_terminal()` needed.
- **Error state**: `Error` is a dedicated fault state. The runtime detects this via `is_error()` and reports `ChildLifecycleEvent::Failed` to the supervisor — distinct from normal completion (`Done`). At the blox level the stub actions always return `Ok`, so this path is unreachable in blox-crate tests; at the system level the concrete action closures propagate the action function's `ActionResult`, so a failed send (full peer channel) makes `results.any_failed()` true and transitions to `Error`.

- Blox crate: `bloxes/ping/`

## State Hierarchy

```mermaid
stateDiagram-v2
    [*] --> Active : dispatch(Start)

    state Operating {
        Active
        Paused
    }

    Active --> Paused : "PingPongMsg::Pong [round == PAUSE_AT_ROUND after increment]"
    Paused --> Active : "PingPongMsg::Resume (timer-delivered)"
    Active --> Error : "PingPongMsg::Pong [results.any_failed()]"
    note right of Active : Pong runs increment_round + forward_ping, then guards — round >= MAX_ROUNDS → Decision::Done (clean self-termination); no guard match → Decision::Stay (no re-entry)
```

    > `[Init]` is engine-implicit (not in the `PingState` enum). The actor enters Init at construction and waits. `dispatch(PingEvent::Lifecycle(LifecycleCommand::Start))` exits Init and enters the first operational state. `dispatch(PingEvent::Lifecycle(LifecycleCommand::Reset))` goes **directly** to `initial_state()` (Active) — it skips Init entirely and `on_init_entry` does NOT fire.
> `Operating` is a composite state (never active). `Active`, `Paused`, and `Error` are leaf states. When `round >= MAX_ROUNDS`, `Active`'s guard returns `Decision::Done` — the actor self-terminates cleanly (no `Done` state needed).
> There is no external `Pause` signal — the transition is internally driven by the round counter.
> The `Error` guard (`results.any_failed()`) is checked before round-based conditions, so action failures take priority.

## States

| State | Kind | Description |
|-------|------|-------------|
| `[Init]` | engine-implicit | Waiting for `dispatch(Start)`; `on_init_entry` resets domain state |
| `Operating` | composite | Groups `Active` and `Paused`; absorbs stray `Pong` while in `Paused` |
| `Active` | leaf | One round in progress; entry sends the first ping (round 1) only on a fresh machine, waits for pong |
| `Paused` | leaf | Exchange suspended; sets a timer on entry; stray `Pong` bubbles to Operating |
| `Error` | leaf, error | Error state; `is_error()` returns `true`; runtime reports `ChildLifecycleEvent::Failed` |

## Events

| Event | Handled by | Rule pattern | Guard outcome | Side effects |
|-------|-----------|--------------|--------------|--------------|
| `PingPongMsg::Pong(_)` | `Active` | Action-Then-Guard | `Decision::Transition(Error)` if `results.any_failed()` | actions `increment_round` + `forward_ping` run first; action failure takes priority |
| `PingPongMsg::Pong(_)` | `Active` | Action-Then-Guard | `Decision::Done` if `round >= MAX_ROUNDS` | actions run first; actor self-terminates cleanly, runtime reports `Done` and the task ends |
| `PingPongMsg::Pong(_)` | `Active` | Action-Then-Guard | `Decision::Transition(Paused)` if `round == PAUSE_AT_ROUND` | actions run first; resume timer armed in `Paused::on_entry` |
| `PingPongMsg::Pong(_)` | `Active` | Action-Then-Guard | `Decision::Stay` otherwise (any round below `MAX_ROUNDS` and not `PAUSE_AT_ROUND`) | `increment_round` advances the round, `forward_ping` sends the one `Ping` for the new round; no re-entry |
| `PingPongMsg::Pong(_)` | `Paused` → bubbles → `Operating` | Bubble | `Decision::Stay` | exchange is paused; pong absorbed by `Operating` |
| `PingPongMsg::Resume(_)` | `Paused` | Action-Then-Guard | `Decision::Transition(Active)` | timer-delivered; `increment_round` advances the round, `forward_ping` sends the one `Ping` for the new round |
| any unhandled | root (no rules) | — | dropped | none |

Each `Pong`/`Resume` handled in `Active`/`Paused` runs the transition actions **before** the guards, so exactly one `Ping` is sent per round, for rounds `1..=MAX_ROUNDS`. Round 1 is sent by `Active::on_entry` (`send_initial_ping`, round 0→1); rounds 2–5 are sent by `forward_ping` after `increment_round`.

Lifecycle commands (`Start`, `Reset`, `Stop`, `Ping`) arrive as `PingEvent::Lifecycle(...)` events via the lifecycle channel and are intercepted by the engine at the VirtualRoot level — they are never matched against state transition rules.

## Context

`PingCtx` is a plain struct with plain fields, generic over `R: BloxRuntime`. There is no `B` generic, no `behavior: B` field, no accessor traits. Action functions take concrete params extracted from the context fields by the codegen.

```rust
pub struct PingCtx<R: BloxRuntime> {
    pub self_id: ActorId,
    pub peer_ref: ActorRef<PingPongMsg, R>,   // target for pong reply
    pub self_ref: ActorRef<PingPongMsg, R>,    // target for timer delivery
    pub timer_ref: ActorRef<TimerCommand, R>,  // timer service channel
    pub current_timer: Option<TimerId>,
    pub round: u32,
}
```

State fields (`current_timer`, `round`) are plain fields on the context struct. The codegen generates wrapper closures that extract fields and pass them to action functions (e.g., `increment_round(&mut ctx.round)`).

No `supervisor_ref` — actors don't hold a reference to their supervisor.

## Message Contracts

Both Ping and Pong share the `PingPongMsg` enum from `ping-pong-messages`.

### Receives (`PingPongMsg`)

| Variant | Payload | Source |
|---------|---------|--------|
| `PingPongMsg::Pong(Pong { round })` | round number | Pong actor |
| `PingPongMsg::Resume(Resume)` | none | Timer task (scheduled by `schedule_resume` in `Paused::on_entry`) |

### Sends

| Target | Message | When |
|--------|---------|------|
| `peer_ref` | `PingPongMsg::Ping(Ping { round: 1 })` | `Active::on_entry` via `send_initial_ping` — only when `round == 0` (fresh machine; sets `round = 1`) |
| `peer_ref` | `PingPongMsg::Ping(Ping { round })` | transition actions `increment_round` + `forward_ping` (fn `send_ping`) on `Pong` in `Active` and on `Resume` in `Paused` (rounds 2–5) |

The runtime notifies the supervisor of lifecycle events (`Started`, `Stopped`, `Failed`, `Reset`, `Alive`) automatically — no explicit sends from actor code.

## Entry / Exit Actions

All action functions are declared in `[[context.actions]]` in `blox.toml` and imported from context crates. There are no blox-local helper methods and no logging actions (logging was removed from blox crates — see AGENTS.md invariant #15):

- `increment_round` — from `blox-ctx-rounds`; `round += 1` (transition action)
- `send_initial_ping` — from `blox-ctx-ping-pong`; fires only when the machine is fresh (`round == 0`): sets `round = 1` and sends `Ping { round: 1 }` to `peer_ref`. No-op on re-entry (`round > 0`), so each round is sent exactly once
- `forward_ping` (fn `send_ping`) — from `blox-ctx-ping-pong`; sends `Ping { round }` to `peer_ref` (transition action, runs after `increment_round`)
- `schedule_pause_timer` (fn `schedule_resume`) — from `blox-ctx-ping-pong`; arms a one-shot `Resume` timer with duration `2000 + round * 500` ms, stores the `TimerId` in `current_timer`
- `cancel_pause_timer` (fn `cancel_timer_by_id`) — from `bloxide_timer::actions`; cancels the stored timer and clears the slot

| State | on_entry | on_exit |
|-------|----------|---------|
| `[Init]` (engine) | reset state via `on_init_entry` (round=0, current_timer=None) — fires only on entry to Init via Stop | — |
| `Operating` | — | — |
| `Active` | `send_initial_ping` | — |
| `Paused` | `schedule_pause_timer` | `cancel_pause_timer` |
| `Error` | — (empty) | — |

## LCA Exit/Entry Examples

### `Active → [Init]` via `Decision::Done` (round >= MAX_ROUNDS)
```
source_path: [Operating, Active]
Decision::Done — no target state

Actions: increment_round, forward_ping  ← run before the guard
Exit:   Active.on_exit      ← (empty)
        Operating.on_exit   ← (empty)
Init:   on_init_entry       ← reset state (round=0, current_timer=None)
Runtime reports: DispatchOutcome::Done → ChildLifecycleEvent::Done; the run
loop then ends the task (the supervisor deregisters the child).
```

### `Active → Paused` (round == PAUSE_AT_ROUND after increment, internally driven)
```
source_path: [Operating, Active]
target_path: [Operating, Paused]
LCA = Operating (index 0)

Actions: increment_round, forward_ping  ← run before the guard
Exit:   Active.on_exit      ← (empty)
Entry:  Paused.on_entry     ← schedule_pause_timer (schedule_resume; 2000 + round * 500 ms)
```
> `Operating::on_exit` does NOT fire — this is an intra-subtree transition.

### `Paused → Active` (timer delivers Resume)
```
source_path: [Operating, Paused]
target_path: [Operating, Active]
LCA = Operating (index 0)

Actions: increment_round, forward_ping  ← send Ping for the new round before re-entry
Exit:   Paused.on_exit    ← cancel_pause_timer (cancel_timer_by_id)
Entry:  Active.on_entry   ← send_initial_ping (no-op: round > 0)
```

### `Active → Error` (results.any_failed())
```
source_path: [Operating, Active]
target_path: [Error]
LCA = None (Operating vs Error are top-level siblings with no common user ancestor)

Exit:   Active.on_exit      ← (empty)
        Operating.on_exit   ← (empty)
Entry:  Error.on_entry      ← (empty; is_error() notifies supervisor via runtime as Failed)
```

### `[Init] → Active` (dispatch Start or Reset)

When `Start` is dispatched in `Init`:
```
current_state = Init

Exit:   on_init_exit        (implicit Init exit hook — default no-op)
Entry:  initial_state() = Active
        Active.on_entry     ← send_initial_ping (round 0→1, sends Ping { round: 1 })
Runtime emits: ChildLifecycleEvent::Started to supervisor
```

When `Reset` is dispatched from any operational state:
```
current_state = (any), source_path = [Operating, ...]

Reset:  full LCA exit chain (leaf → root), then entry chain for initial_state()
        Init is SKIPPED — on_init_entry / on_init_exit do NOT fire,
        so round is NOT reset (it keeps its current value)
Entry:  Active.on_entry     ← send_initial_ping (no-op if round > 0)
Runtime emits: ChildLifecycleEvent::Started to supervisor
```

## Constants

| Name | Value | Description |
|------|-------|-------------|
| `MAX_ROUNDS` | 5 (`u8`) | Total ping-pong exchanges before `Decision::Done` (clean self-termination); declared in `bloxes/ping/blox.toml` (`[[consts]]`), imported into guards via `spec_imports` |
| `PAUSE_AT_ROUND` | 2 (`u8`) | Round at which Active internally pauses itself; declared in `bloxes/ping/blox.toml` (`[[consts]]`) |

The pause duration is not a constant: `schedule_resume` derives it from the current round as `2000 + round * 500` ms.

## Acceptance Criteria

Blox-crate unit tests run against the blox-level **stub** spec (per invariant #18,
concrete actions are wired only at the system level). The tests therefore verify
topology, guards, and lifecycle semantics — not action side effects. Action
behavior is covered by the runnable demos (`examples/tokio-demo`).

- [x] `dispatch(PingEvent::Lifecycle(LifecycleCommand::Start))` exits Init and enters `Active`
- [x] `PingPongMsg::Pong(n)` in `Active` stays (`Decision::Stay`, no re-entry) when round guards don't fire
- [x] `PingPongMsg::Pong(n)` in `Active` with `round == PAUSE_AT_ROUND` transitions to `Paused`
- [x] `PingPongMsg::Resume` in `Paused` transitions to `Active`
- [x] Stray `PingPongMsg::Pong(n)` in `Paused` bubbles to `Operating` → `Stay` (no message sent)
- [x] `PingPongMsg::Pong(n)` in `Active` with `round >= MAX_ROUNDS` triggers `Decision::Done` (clean self-termination; machine parks in Init, run loop ends the task)
- [x] `is_error(&PingState::Error)` returns `true`; other states return `false`
- [x] With stub actions (all `Ok`), a full peer channel does NOT trigger the `Error` guard (`results.any_failed()` is false)
- [x] `dispatch(PingEvent::Lifecycle(LifecycleCommand::Reset))` from Init goes directly to `initial_state()` (Active); `on_init_entry` does NOT fire
- [x] Unknown events bubble to root (no root rules) and are silently dropped

## Implementation Notes

- `R: BloxRuntime` is the only runtime bound. Timer functionality comes from `bloxide-timer` (`TimerCommand`, `TimerId`, and the `cancel_timer_by_id` action in `bloxide_timer::actions`); the domain-level `schedule_resume` / `send_ping` / `send_initial_ping` action functions come from `blox-ctx-ping-pong`.
- `try_send` is used (not `send`) throughout because entry/exit handlers and transition actions are synchronous `fn` — they cannot await.
- `self_ref` in the context is needed because `schedule_resume` needs a target `ActorRef` to deliver `Resume` to.
- `timer_ref` in the context is the `ActorRef<TimerCommand, R>` channel to the timer service.
- `cancel_pause_timer` is called in `Paused::on_exit` to prevent stale timer deliveries after leaving `Paused`.
- Domain state is initialized by the generated `on_init` body (`round = 0`, `current_timer = None`), which runs in `on_init_entry` — i.e. on entry to Init via Stop, not on Reset. After a `Reset`, `round` keeps its current value and `send_initial_ping` is a no-op.
- The blox crate depends on context crates (`blox-ctx-rounds`, `blox-ctx-ping-pong`) and `bloxide-timer` (for `TimerCommand`/`TimerId`). It does NOT depend on `bloxide-log` (invariant #15) or any impl crate (invariant #9). Concrete action closures are generated at the system level from `system.toml` (invariant #18).
- See `spec/architecture/07-supervision.md` for how the runtime manages lifecycle.
- See `spec/architecture/11-action-crate-pattern.md` for the layered architecture.

## Acceptance Criteria → Test Mapping

All tests live in `bloxes/ping/tests/ping.rs` and use `TestRuntime`:

| Acceptance Criterion | Test Function |
|---|---|
| Start exits Init → Active | `start_enters_active_and_sends_first_ping` |
| Pong in Active continues round (stay) | `pong_response_advances_round` |
| Pong at PAUSE_AT_ROUND → Paused | `pong_response_at_pause_round_transitions_to_paused` |
| Resume in Paused → Active | `timer_fires_resume_transitions_to_active` |
| Pong with round >= MAX → Decision::Done (Init, task ends) | `done_after_max_rounds` |
| `is_error` true only for Error | `error_state_is_error` |
| Reset → initial_state() directly | `terminate_resets_to_initial_state` |
| Stray Pong in Paused absorbed by Operating | `stray_pong_in_paused_is_absorbed_by_operating` |
| Stub actions never fail → no Error transition | `pong_with_stub_actions_does_not_transition_to_error` |
| Unknown event bubbles to root (no root rules), silently dropped | `unhandled_event_bubbles_to_root_and_is_dropped` |

The `Error` path has a two-level story: at the **blox level** the stub actions always return `ActionResult::Ok`, so `results.any_failed()` is never true and `Error` is unreachable in blox-crate tests (`pong_with_stub_actions_does_not_transition_to_error` pins this). At the **system level** the generated concrete closures return the action function's `ActionResult` verbatim, so a failed `send_ping` (e.g. a full peer channel) makes `results.any_failed()` true and the guard transitions to `Error`.

## blox.toml

The full declarative source is `bloxes/ping/blox.toml`; the topology-relevant parts:

```toml
[topology]
spec_imports = [
    "bloxide_core::transition::ActionResult",
    "crate::{MAX_ROUNDS, PAUSE_AT_ROUND}",
]

[[topology.states]]
name = "Operating"
composite = true

[[topology.states]]
name = "Active"
parent = "Operating"
initial = true

[[topology.states]]
name = "Paused"
parent = "Operating"

[[topology.states]]
name = "Error"
error = true

# Operating: composite state, catches Pong to prevent bubbling
[[topology.transitions]]
state = "Operating"
event = "PingPongMsg::Pong(_)"
target = "stay"

# Active: entry sends the first ping (round 0→1); each Pong advances the round
# and forwards exactly one ping for the new round (stay — no re-entry).
[[topology.entry]]
state = "Active"
actions = ["Self::send_initial_ping"]

[[topology.transitions]]
state = "Active"
event = "PingPongMsg::Pong(_)"
target = "stay"
actions = ["Self::increment_round", "Self::forward_ping"]

[[topology.transitions.guards]]
condition = "results.any_failed()"
target = "Error"

[[topology.transitions.guards]]
condition = "ctx.round >= MAX_ROUNDS as u32"
target = "done"

[[topology.transitions.guards]]
condition = "ctx.round == PAUSE_AT_ROUND as u32"
target = "Paused"

# Paused: entry schedules timer, exit cancels it; Resume advances the round
# and forwards one ping, re-entering Active
[[topology.entry]]
state = "Paused"
actions = ["Self::schedule_pause_timer"]

[[topology.exit]]
state = "Paused"
actions = ["Self::cancel_pause_timer"]

[[topology.transitions]]
state = "Paused"
event = "PingPongMsg::Resume(_)"
target = "Active"
actions = ["Self::increment_round", "Self::forward_ping"]
```
